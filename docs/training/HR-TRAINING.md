# HR Training Track (3 staff)

HR staff manage people-related public content and assigned citizen
correspondence. HR users do **not** receive technical administration rights;
permissions follow the Department Content Owner pattern (department scope).

## Modules (in the training environment)

1. **Officials**: create/edit name, title, biography, photo (with meaningful
   alt text), department; flag the **Head of department** where applicable.
   Never publish unverified names, private staff details, or personal contacts.
2. **Departments**: overview, responsibilities, public contacts, linked
   services/documents; confirm the public department page renders correctly.
3. **Vacancies**: title, reference, grade, employment type, description,
   responsibilities, requirements, opening/closing dates, application
   instructions, advert document. Expired vacancies read **Closed** — never
   republish an old vacancy as open; create a new record for a new intake.
4. **Wards**: directory entries and boundary descriptions (no invented
   boundaries; GIS data is a council dependency).
5. **Enquiries/feedback**: view assigned items, add internal notes (private),
   change status through the workflow (New → In progress → Resolved/Closed),
   route to departments where permitted. Never publish complaint contents;
   never copy private details into public CMS fields.
6. **Privacy responsibilities**: see `DATA-PROTECTION-TRAINING.md`.

## Common mistakes
Publishing draft profiles; leaving expired vacancies open; uploading photos
without alt text; putting internal notes where citizens can see them (notes
are staff-only by design — keep them factual regardless).
